# 用語集

nvecd での用語の意味です。一般的な機械学習の用法より狭い場合は、ここではコードが実装しているほうの意味を採ります。

**適応的な統合 (adaptive fusion)** — 配分を設定値の定数ではなく、クエリアイテムの共起の隣接数から導く統合検索です。ベクトル側の重みは、隣接が 0 件のときの `adaptive_max_alpha` から、`adaptive_maturity_threshold` 件に達したときの `adaptive_min_alpha` まで動きます。クエリごとに `adaptive=on` で、全体には `similarity.adaptive_fusion` で有効にします。[統合検索](./fusion.md) を参照してください。

**ANN 索引 (ANN index)** — ベクトル検索が使う近似最近傍の構造です。類似検索エンジンが所有し、`similarity.index_type` で `flat`・`hnsw`・`ivf` から選びます。[ベクトル検索](./vector-search.md) を参照してください。

**配分 (blend weight)** — 統合検索が正規化済みの 2 つのスコア列に掛ける重みの組で、ベクトル側が `similarity.fusion_alpha`、イベント側が `similarity.fusion_beta` です。片方のソースしか候補を出さなかったときは、残ったほうの重みが 1 になります。[統合検索](./fusion.md) を参照してください。

**チェックポイントサイドカー (checkpoint sidecar)** — スナップショットの隣に `<snapshot>.walseq` という名前で書かれるファイルで、そのスナップショットが含む先行書き込みログのシーケンス番号を保持します。WAL を有効にした復旧では、この番号より後のレコードだけを再生します。[永続化](./persistence.md) を参照してください。

**共起 (co-occurrence)** — 同じコンテキストの中で操作された 2 つのアイテムの関連です。コンテキストを共有するたびに 2 つのイベントスコアの積が寄与し、それが積み上がってペアごとに 1 つの対称なスコアになります。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**共起検索 (co-occurrence search)** — `SIM <item> <k> using=events` です。クエリアイテムの共起の隣接をスコア順に返します。スコアは累積した生の値です。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**コンテキスト (context)** — `EVENT` コマンドのまとめ方を決めるキーです。セッション、ユーザー、カートなど、2 つの操作を同じまとまりとして扱う根拠になるものを指定します。同じコンテキストのアイテム同士が共起します。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**cosine** — 既定の距離尺度です。スコアは書き込み時に記録したノルムから求めたコサイン類似度で、値が大きいほど近いことを表します。[ベクトル検索](./vector-search.md) を参照してください。

**減衰 (decay)** — すべての共起スコアを `events.decay_alpha` 倍する処理で、`events.decay_interval_sec` 秒ごとに背後のスケジューラが実行し、あわせて定期的に枝刈りします。古い行動が支配し続けないようにし、スコアの増加に歯止めをかけるのがこの仕組みです。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**重複除去ウィンドウ (dedup window)** — `events.dedup_window_sec` のことです。コンテキスト・アイテム・スコアが同じ `ADD` イベントがこのウィンドウ内に再び届いた場合、応答は成功ですが適用はされません。クライアントの再送で共起スコアが膨らまないようにするためです。`SET` と `DEL` は時間のウィンドウではなく、そのペアについて記録された状態と照らして重複を判定します。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**次元 (dimension)** — ストア内のすべてのベクトルが持つ成分数です。最初に保存されたベクトルで確定し、以降のベクトルはそれに一致する必要があります。最初の書き込みより前は `vectors.default_dimension` が ANN 索引の大きさを決めます。[ベクトル検索](./vector-search.md) を参照してください。

**距離尺度 (distance metric)** — `vectors.distance_metric` のことで、`cosine`・`dot`・`l2` のいずれかです。サーバーが行うすべてのベクトル比較に適用されます。[ベクトル検索](./vector-search.md) を参照してください。

**dot** — 内積による尺度です。スコアは生の内積なので上限がなく、ベクトルの大きさの影響を受けます。[ベクトル検索](./vector-search.md) を参照してください。

**イベント (event)** — 報告された 1 件の操作、すなわち `EVENT <context> <ADD|SET|DEL> <item> [<score>]` です。3 つの形式はいずれもコンテキストのリングバッファに追加され、違いは重複判定の基準にあります。`ADD` は重複除去ウィンドウ、`SET` はそのコンテキストとアイテムについて最後に記録されたスコア、`DEL` は既に削除済みかどうかで判定します。`DEL` はスコア 0 で保存されるため、新しい共起の寄与を作りません。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**flat 索引 (flat index)** — `similarity.index_type` の既定値です。索引構造を持たず、クエリは保存済みのベクトルを直接走査します。サンプリングが働かない限り厳密解です。[ベクトル検索](./vector-search.md) を参照してください。

**統合検索 (fusion search)** — `SIM <item> <k> using=fusion` で、既定のモードです。両方の検索を実行して候補集合の和をとり、ソースごとに別々にスコアを正規化してから、配分に従って足し合わせます。[統合検索](./fusion.md) を参照してください。

**HNSW** — グラフ構造の ANN 索引です。`index_type: hnsw` で選び、`hnsw_m`・`hnsw_ef_construction`・`hnsw_ef_search` で調整します。[ベクトル検索](./vector-search.md) を参照してください。

**アイテム ID (item ID)** — クライアントがアイテムに付ける名前の文字列です。イベント・ベクトル・メタデータは 1 つの ID 空間を共有しており、同じアイテムについて 2 つの信号を統合できるのはこのためです。[TCP プロトコル](./protocol.md) を参照してください。

**IVF** — 転置ファイル型の ANN 索引です。ベクトルを `ivf_nlist` 個のクラスタに分割し、クエリ時に `ivf_nprobe` 個を探索します。`ivf_train_threshold` 件のベクトルが揃うと学習し、それ以降の書き込みは `ivf_seal_threshold` に達するまで書き込みバッファに溜めてから転置リストへ公開します。[ベクトル検索](./vector-search.md) を参照してください。

**L2** — ユークリッド距離による尺度です。報告されるスコアは `1 / (1 + 距離)` なので、他の尺度と同じく値が大きいほど近いことを表します。[ベクトル検索](./vector-search.md) を参照してください。

**メタデータフィルタ (metadata filter)** — `SIM` と `SIMV` の `filter=` オプションです。条件は `キー<演算子>値` の形で、演算子は `=`、`:`、`!=`、`>`、`<`、`>=`、`<=`、`in(a|b|c)` です。カンマで区切った複数の条件はすべて一致する必要があります。値は書き方から真偽値・整数・浮動小数・文字列のいずれかとして解釈されます。[TCP プロトコル](./protocol.md) を参照してください。

**min_score** — スコアを付けたあとで、この値を下回る結果を落とすオプションです。指す尺度はモードごとに違い、`using=vectors` では類似度、`using=fusion` では正規化した統合値、`using=events` では生の共起の累積和です。[TCP プロトコル](./protocol.md) を参照してください。

**負のシグナル (negative signal)** — `events.negative_signals` を有効にすると、`DEL` イベントが、削除されたアイテムとコンテキストに残るアイテムとの共起スコアから、各アイテムのスコアと `events.negative_weight` の積を差し引きます。0 以下になったペアは結果に現れなくなります。既定は無効で、そのときの `DEL` は新しいペアへの寄与を終わらせるだけです。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**正規化 (スコア)** — 統合検索が、統合の前に各ソースの候補一覧へ適用する min-max による再スケールです。上限のない共起の累積和と、上限のある類似度を同じ範囲に揃えます。手元の候補に対して相対的なので、そのソースで最も弱い候補はそのソースからの寄与が 0 になります。候補が 1 件だけの場合と、スコアの幅が 1e-4 未満の場合は、再スケールせず [0, 1] に丸め込みます。[統合検索](./fusion.md) を参照してください。

**正規化 (ベクトル)** — ベクトルを長さ 1 に揃えることです。サーバーは送られたままの値を保存し、正規化しません。cosine の尺度は、書き込み時に記録したノルムで割ることで対応します。単位ベクトルを使いたいクライアントは、単位ベクトルを送ります。[ベクトル検索](./vector-search.md) を参照してください。

**クエリキャッシュ (query cache)** — `SIM` と `SIMV` の結果をメモリ上に保持するキャッシュです。エントリが保存されるのはクエリに `cache.min_query_cost_ms` 以上かかった場合だけで、キーには世代番号が含まれるため、元のストアへの書き込みは該当する空間を無効化します。絞り込みのない `SIMV` は既定の方針ではキャッシュされません。[キャッシュ](./caching.md) を参照してください。

**復旧 (recovery)** — サーバーが起動時に行うことです。最新の有効なスナップショットを読み込み、WAL が有効な場合はそのスナップショットのチェックポイント以降のログレコードを再生してから、書き込みの受け付けを始めます。[永続化](./persistence.md) を参照してください。

**リングバッファ (ring buffer)** — コンテキストごとの固定長のイベントバッファで、大きさは `events.ctx_buffer_size` です。新しいイベントが最も古いものを上書きし、後続のイベントが作る共起ペアの相手になるのはバッファに残っているイベントだけです。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**サンプリング (sampling)** — `similarity.sample_size` で制御する近似的な走査です。コーパスがこの値の 2 倍を超えると、ベクトル検索は全件ではなく無作為な標本を採点します。0 にするとすべての検索が厳密になります。[ベクトル検索](./vector-search.md) を参照してください。

**スコア (score)** — 2 つの別々のものを指します。`EVENT` では、クライアントがその操作に与える 0 から 100 の整数の重みです。`SIM` や `SIMV` の結果では、検索が求めた順位付けの値で、ワイヤ上には小数点以下 4 桁で出力されます。[TCP プロトコル](./protocol.md) を参照してください。

**スナップショット (snapshot)** — ある時点の設定・イベント・共起索引・ベクトル・メタデータを収めた 1 つのファイルです。`DUMP SAVE` で書き出され、`snapshot.interval_sec` を設定するとスケジューラも書き出します。読み戻すのは `DUMP LOAD` か起動時の復旧です。[永続化](./persistence.md) を参照してください。

**最小サポート (minimum support)** — `events.min_support` のことです。絶対値がこれを下回る共起の辺は、索引の枝刈りのときに削除されます。スコアが減衰していく長時間稼働の索引で、メモリを抑えるための仕組みです。0 で無効になります。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**時間減衰つき共起 (temporal co-occurrence)** — `events.temporal_cooccurrence` を有効にすると、各ペアの寄与に、2 つのイベントの時間差と `events.temporal_half_life_sec` から求めた減衰係数が掛かります。時間的に離れたイベントほどアイテム同士を弱く結び付けます。減衰はペア単位で計算されるため、逐次更新でも一括再構築と同じ索引になります。[イベントと共起](./events-and-co-occurrence.md) を参照してください。

**top-k** — 検索に要求する結果の件数で、`SIM` では 2 番目、`SIMV` では 1 番目の引数です。正の整数で、`similarity.max_top_k` 以下でなければならず、これはコマンドの解析時に検査されます。[TCP プロトコル](./protocol.md) を参照してください。

**ベクトル検索 (vector search)** — `SIM <item> <k> using=vectors`、または保存済みのアイテムに属さなくてよいクエリベクトルを使う `SIMV <k> <floats>` です。設定した距離尺度で順位を付け、イベントは一切見ません。[ベクトル検索](./vector-search.md) を参照してください。

**先行書き込みログ (WAL)** — 受理した書き込みを適用する前に追記していくログです。スナップショットに含まれていないぶんを再起動時に再生できます。既定では無効です（`wal.enabled`）。[永続化](./persistence.md) を参照してください。
